## Implementation decisions to review

- **Multiple listed professors — removed:** The owner deferred this requirement after the overnight review. Professor search/filtering now treats `instructor_name` as one literal string. Array support and guessed delimiters have been removed from SQL, Python, and JavaScript. The earlier “Jane Smith & Alex Rivera” example was invented to explain the parser, not supplied by the owner or found in the local data. Review an actual example before adding support later.
- **Cached refresh (#20):** The old table stays usable during a check. If saved evaluations change, **Show updated data** replaces the table data without a page reload and retains search, filters, and comparison settings. Otherwise the banner says **No new data found for [period]**. An initially empty result displays newly found data immediately. Optional browser notifications announce completion while the tab is open; permission is unrelated to updating the table. A renewable per-course database lock prevents duplicate scrapes. These UI outcomes already implement the requested refresh-button/no-data behavior.
- **Report failure behavior — reverted:** At the owner's request, a report returning `scrape_failed` again logs a warning and skips to the next report, without the added course-failure flag or stop. The existing eight-attempt retry behavior is preserved. A [deferred TODO](TODO.md#scrape-failure-handling-deferred) now calls for distinguishing transient from persistent failures and deciding how retries and partial success should affect course freshness. No new failure classification or retry policy was implemented.
- **Recorded names:** Professor separation retains exact recorded names rather than stripping punctuation, keeping it consistent with exact-name search. No professor-name grouping is introduced.
- **One-time workload histogram:** Added `one-time-scripts/plot_workload_histogram.py` at the owner's request. “All classes” uses the same population as percentiles: one full-precision, response-weighted average per existing course group across all available years/seasons, with equal weight between groups. The overlaid normal uses the mean and sample SD of those averages and is scaled to histogram counts. Review that population choice if individual sections were intended. The default local export produced 5,830 groups, mean 3.056047, sample SD 0.597294 (604,966 workload responses; 2015–2026). The optional read-only database mode produced the same results against the disposable local database. The generated PNG was visually inspected; it represents the local export, not a fresh live query. No app code, grouping rules, migrations, or test files changed.
- **Exploratory size-weighted percentiles:** Added and ran `one-time-scripts/analyze_size_weighted_percentiles.py` before implementing the setting. The primary analysis uses each metric's valid response count divided by distinct observed terms for its existing course group, including summer/intersession and combining sections within a term. On the local export, median absolute shifts are 11.36 points for Overall Quality and 1.75 for Workload; 84.2% of quality courses and no workload courses move at least five points. Five points for at least 20% of courses is an explicit product-review threshold, not a significance test; all five non-workload metrics meet it. The report includes full lookup tables, per-course results, tail changes, ties, and missing-answer sensitivity. All six equal-course baselines matched the production builder; weighted lookups were monotone, and both generated charts were inspected. This initial analysis did not change the app.
- **Class-size weighting checkbox:** The owner approved implementation and accepted response counts for estimating class size. **Advanced Options → Statistics → Weight percentiles by average class size** uses the analyzed formula for each metric and the existing course groups. It starts unchecked; I made its saved preference independent of **Show percentiles**, so choosing one does not reset the other. The selection applies across course/professor results, filters, separations, score tooltips, and CSV exports. CSV includes the selected weighting, and the percentile caption identifies weighted mode. Scores, response statistics, row identities, and significance calculations keep their original inputs. Version 3 caches both 401-value lookups together; the existing counter, transaction, and first-request format refresh handle rebuilding. No additional SQL migration is needed. Review the default/persistence and wording in the local preview; browser verification remains with the owner as requested.
- **Percentile population (#21):** The benchmark covers all departments and all available years, with one response-weighted mean per existing logical course group and equal weight between groups. The owner's compact-map proposal replaces the earlier maintenance schedule: store 401 percentile values per metric for 1.00–5.00. Course means and lookup scores round to the nearest hundredth, with halfway values rounded up; tied course means use midranks. This rounding affects percentiles only, not Welch inputs. Review the population and tie convention.
- **Percentile counter:** The owner raised the threshold to 1,000 newly inserted evaluation reports across the database. Each report aggregates student responses for a course section and term. For scale, the local export contains 625,651 valid Overall Quality ratings across 33,502 reports; these are rating responses, not unique people. A scrape adding 20 reports increments by 20; metadata-only/no-results checks increment by zero. The database trigger also counts imports. At 1,000, rebuild at the end of a scrape that saved data or on the next benchmark request, then reset the counter. The first request builds a missing/old-format mapping once. Existing-row corrections/deletions can use the explicit rebuild command. Concurrent writes/rebuilds share a row lock so counts are not lost; a rebuild failure keeps the old mapping and pending count without failing the scrape. An open page retains one common snapshot; a later page visit gets the latest. See [migration instructions](migrations/README.md).

- **Adding comparisons (#13):** An exact duplicate course/professor selection does not consume another slot. Different course codes in an existing cross-listed group may still be displayed together; shared evaluation records disable the independent-samples comparison. Review this duplicate-selection policy.
- **Comparison layout (#13–14):** Tables remain side by side with a 520px starting width and horizontal scrolling. Desktop review found that a professor table with long course-group labels could spill into its neighbor; result panels now also respect the table's minimum content width. Verified that both tables stay inside their panels at 1,132px and 1,710px desktop widths. General controls appear once; titles, grouping controls, and refresh notices stay with each result. A remaining single result returns to the single-result layout. The owner is reviewing the overall UI for further changes.

The existing records do not identify individual respondents across distinct reports, so that independence assumption remains. [Calculation details](docs/COMPARISONS.md).
